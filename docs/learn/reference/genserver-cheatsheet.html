GenServer cheat sheet

A GenServer is a process that loops: take one message, run a callback, keep the state it returns. You write the callbacks; OTP writes the loop.

Three ways to send, three callbacks

Client sideServer callbackCallerUse when
GenServer.call(pid, msg, timeout \\ 5000)handle_call(msg, from, state)blocks until the reply or the timeout, then exitsthe caller needs an answer, or should be slowed down (back-pressure). Every Quacks move.
GenServer.cast(pid, msg)handle_cast(msg, state)returns :ok at oncefire and forget, and losing track of failures is fine. Quacks never casts.
send(pid, msg), Process.send_after/3, monitors, PubSubhandle_info(msg, state)does not waittimers, :DOWN notices, broadcasts, anything not sent through the GenServer API.

Callbacks and what they return

CallbackReturnsMeaning
init(arg){:ok, state}, {:ok, state, timeout}, :ignore, {:stop, reason}Set up the first state. Runs inside the new process, while start_link waits.
handle_call/3{:reply, reply, state}, {:reply, reply, state, timeout}, {:noreply, state}, {:stop, reason, reply, state}Answer the caller and keep the new state. :noreply means you will answer later with GenServer.reply/2.
handle_cast/2, handle_info/2{:noreply, state}, {:noreply, state, timeout}, {:stop, reason, state}Keep the new state; nobody waits for a reply.
terminate(reason, state)anythingLast words. Runs on :stop, on a raise in a callback, and on a supervisor shutdown if the process traps exits.

A timeout in a return tuple is the server’s idle timer: no message within it, and handle_info(:timeout, state) runs. Quacks uses @idle_timeout, 2 hours. The caller’s timeout is the third argument of call.

Rules of thumb

  • Client functions hide the messages. Callers use GameServer.apply/3, never a raw GenServer.call with a tuple. One module owns its protocol.
  • One message at a time. The mailbox serialises everything, so state needs no locks. Anything slow in a callback delays every caller behind it.
  • Prefer call. It reports errors back and gives back-pressure. Reach for cast only when you truly do not care.
  • A call can fail three ways: no process (:noproc), the server dies during the call (its exit reason), or no reply in time (:timeout). Quacks’ call/2 turns only :noproc, :normal, :shutdown and :killed into {:error, :not_found}.
  • Find processes by name, not pid. A Registry with {:via, Registry, {name, key}} maps a key to the current pid.
  • Pick the restart type on purpose. :permanent for services, :transient for jobs that may finish, :temporary when a restart would not help (a game whose state died with it).
  • Monitor to watch, link to share fate. Process.monitor/1 gives a :DOWN message. A link kills both unless one traps exits.
