Glossary

The words this course uses for Elixir, OTP and LiveView, one meaning each. Lessons use these terms and avoid the aliases.

Game terms (chip, pot, seat, round) live in the repo’s own docs/CONTEXT.md.

Processes

Process
A lightweight, isolated unit of execution on the BEAM with its own memory and a mailbox; processes share nothing and talk only by messages. In this course it never means an OS process. Avoidthread, worker, actor
BEAM
The Erlang virtual machine that runs Elixir code and schedules every process. Quacks runs one BEAM node on one Fly machine. Avoidthe runtime, Erlang VM (fine, but say BEAM)
Mailbox
The queue of messages waiting for one process. The process handles them one at a time, which is why a GameServer never sees two moves at once. Avoidinbox, message queue, event loop
GenServer
An OTP behaviour for a process that loops forever: take a message from the mailbox, run a callback, keep the new state. Quacks.GameServer is one, one per game. Avoidservice, server class, store (the analogy is fine, the term is not)
call
Sending a message to a GenServer and waiting for its reply (GenServer.call/2, 5 s timeout by default). Its fire-and-forget sibling is cast; Quacks never uses it. Avoidrequest, invoke, RPC
PubSub
A publish/subscribe bus between processes (Quacks.PubSub). A process subscribes to a topic string such as "game:abcdef"; a broadcast sends a message to every subscriber’s mailbox. Avoidevent bus, channel, websocket push
Registry
A name table from a key to a pid. Quacks.GameRegistry maps a game id to its GameServer. Avoidlookup table, directory
Via name
A process name of the form {:via, Registry, {Quacks.GameRegistry, id}}, so callers can reach a process by a key instead of a pid. Avoidalias, handle
cast
Sending a message to a GenServer without waiting (GenServer.cast/2, handled in handle_cast/2). Quacks never uses it. Avoidasync call, fire-and-forget call
Call timeout
How long a caller waits in call before it exits with :timeout; 5 s by default. Not the same as the idle timeout, the fourth element of a callback’s return tuple, which wakes the server with :timeout after silence (2 h in the GameServer). Avoidtimeout (say which one)
Supervisor
A process whose only job is to start child processes and start them again, by its strategy, when they exit. Quacks.Supervisor is the root. Avoidmanager, watchdog, parent
DynamicSupervisor
A supervisor that starts with no children and adds them at runtime. Quacks.GameSupervisor gets one GameServer per game. Avoidpool, worker manager
Restart strategy
What a supervisor restarts when one child exits: :one_for_one only that child, :one_for_all every child, :rest_for_one that child and the ones started after it. Avoidrestart policy (that is the child’s restart type)
Restart type
A child’s own setting: :permanent always restarted, :transient only after an abnormal exit, :temporary never. The GameServer is :temporary. Avoidrestart strategy
Link
A two-way bond between processes: when one exits abnormally, the exit signal kills the other, unless it traps exits. Supervisors link to their children; a Registry links to the processes registered in it. Avoidconnection, dependency
Trapping exits
Process.flag(:trap_exit, true): exit signals from links arrive as {:EXIT, pid, reason} messages instead of killing the process. The GameServer traps exits so a shutdown runs terminate/2. Avoidcatching exits (that is catch :exit around a call)
Monitor
A one-way watch on another process (Process.monitor/1): when it ends, the watcher gets {:DOWN, ref, :process, pid, reason} and lives on. Avoidlink, heartbeat, listener

LiveView

LiveView
A process per browser tab that holds the tab’s state, renders HTML from it and handles its events. QuacksWeb.GameLive is the game page’s LiveView. Avoidcomponent, page controller, view
LiveView socket
The struct a LiveView passes through every callback (socket); it carries the assigns. Not the network connection, which this course calls the websocket. Avoidconnection (for the struct), the socket (for the websocket)
Assigns
The map of state on the LiveView socket (socket.assigns), read in templates as @name and set with assign/2. Avoidstate, props
mount/3
The LiveView callback that sets up the first assigns. It runs twice: once for the plain HTTP render, once in the connected process that lives with the tab. Only the second has connected?(socket) true. Avoidconstructor, componentDidMount
handle_event/3
The LiveView callback for an event from the browser, such as a phx-click. Avoidclick handler, onClick
handle_info/2
The callback for any other message in the process’s mailbox, such as a PubSub broadcast. Avoidlistener, subscription callback
Diff
The JSON patch LiveView sends to the browser after a render: only the dynamic parts of the template whose assigns changed. Avoidupdate, delta, patch (fine in passing)
Connected mount
The second run of mount/3, in the LiveView process that lives with the tab, where connected?(socket) is true. The first run answers plain HTTP. Avoidhydration, client mount
Statics and dynamics
The two halves a HEEx template compiles to: the literal HTML between expressions (statics, sent once) and the {...} slots (dynamics, sent again when they change). Avoidtemplate and data, markup and values
Change tracking
LiveView’s record of which assigns changed since the last render, so it re-runs and sends only the dynamics that read them. assign/3 with an equal value is not a change. Avoiddirty checking, reactivity
Comprehension
A for or :for loop in a template. LiveView sends its row statics once and tracks rows by index, or by :key when given one. Avoidmap, list render
Stream
A LiveView collection (stream/4, stream_insert/4) whose items go to the browser with DOM ids and are then dropped from the server’s memory. AvoidElixir Stream (a lazy enumerable, unrelated)
Temporary assigns
Assigns reset to a default after every render, so the server does not keep them. The older tool for large lists; streams cover most uses now. Avoidephemeral state

Reading Elixir

Atom
A constant whose value is its own name, written :draw. Atoms are never garbage-collected, so code never makes them from user input. Avoidsymbol, enum value
Tuple
A fixed-size, ordered group of values, written {:white, 2}. A tagged tuple starts with an atom that names its shape, such as {:ok, game} or {:buy, chips}. Avoidarray, pair, record
Struct
A map with a fixed set of keys, defaults and a module name, written %Quacks.Game{}. Updating an unknown key raises. Avoidobject, class instance, record
Immutable
A value never changes after it is made. %{g | round: 2} builds a new struct; g stays as it was. Avoidfrozen, read-only, constant
Pattern match
Checking a value against a shape and binding names from it, as in {:ok, game} = result. A failed = match raises MatchError. Avoiddestructuring (it is more), assignment
Function clause
One of several definitions of the same function. Elixir runs the first clause whose pattern and guard fit the arguments. Avoidoverload, case branch
Guard
The when part of a clause, built only from a fixed set of side-effect-free checks such as is_integer(seat). Avoidcondition, precondition
Pipe
The |> operator: it passes the value on its left as the first argument of the call on its right. Avoidchain, fluent call
with
A chain of pattern matches (pattern <- expr) that runs its do block when all match and otherwise returns the first value that did not. Avoidtry block, promise chain
Result tuple
The convention {:ok, value} or {:error, reason} for a function that can fail as a normal outcome. Game.apply/3 returns one. AvoidEither, response object, exception
Pure function
A function whose result depends only on its arguments and which changes nothing else. The whole engine, Quacks.Game, is pure. Avoidstateless function, helper
RNG state
The random generator’s state as a value, stored in game.rng and advanced with :rand.uniform_s/2. Seed plus actions then rebuild the same game. Avoidseed (the seed only starts it), random
