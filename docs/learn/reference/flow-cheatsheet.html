A tap’s round trip

One move, Draw a chip in tab A, in nine hops. The server is the store: one process per game holds the state, one process per tab renders it.

Rules of thumb

  • Two taps at once are queued in the GameServer’s mailbox and applied one after the other. No locks.
  • call, never cast: every tab gets an answer, and waiting gives back-pressure.
  • Subscribe only when connected: the first mount/3 answers plain HTTP; the second runs in the tab’s long-lived process.
  • The struct never reaches the browser. It travels between processes in memory. Only HTML diffs cross the network.
  • Errors are values. An illegal move is {:error, {:illegal_action, action, phase}}, shown as a flash.
  • Game gone? call/2 turns a missing or dying server into {:error, :not_found}, and the tab goes back to the lobby.
