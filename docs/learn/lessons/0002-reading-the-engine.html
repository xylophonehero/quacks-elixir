In lesson 1 the GameServer handed every move to Quacks.Game. That module is the whole rulebook, written as plain functions on one value. Today you read it.

The shapes you will meet

Four kinds of value cover almost all of the engine.

ElixirExample in QuacksClosest TypeScript
atom:draw, :potionsa string literal type, "draw"
tuple{:white, 2}, {:ok, game}a fixed-length array, ["white", 2]
map%{0 => player}an object or Map
struct%Quacks.Game{}an interface with defaults

A chip is the tuple {:white, 2}: colour, then value. A move is an atom like :draw or a tagged tuple like {:buy, [{:green, 2}]}. The first element is the tag, the way type tags a TypeScript discriminated union.

The game is one struct with fifteen fields. Note rng and log; both matter below.

Nothing changes in place

Every value is immutable. %{g | log: [entry | log]} builds a new struct with one key replaced; the old g is untouched. [entry | log] builds a new list with entry in front, which is why the log is newest first.

React ≈{...g, log: [entry, ...g.log]}, the spread you write in every reducer. In Elixir it is the only way, so you never need Object.freeze or Immer.

= matches, and so do function heads

In Elixir = is a match. {:ok, game} = result checks that result is a two-tuple starting with :ok and binds game. If the shape is different, it raises (Elixir guide: Pattern matching).

A function can have several clauses. Elixir tries them top to bottom and runs the first whose pattern, and when guard if any, fits. This replaces most switch and if chains. Here is one player’s legal moves in the potions phase, one clause per sub-phase:

A map pattern only names the keys it cares about. %{fortune_card: :b4} matches any map or struct whose fortune_card is :b4, whatever else it holds. The second clause is the default; the _ prefix marks a variable the body ignores.

React ≈A switch (action.type) where each case can also destructure, check nested values and bind names, all in the case label.

The contract: {:ok, game} or {:error, reason}

Now the function from lesson 1’s hop 5, read slowly.

  • Line 646. %__MODULE__{} = game accepts only a %Quacks.Game{}. __MODULE__ is the current module’s name.
  • Line 649. The only check is legal_actions/2. The UI’s buttons come from the same list, so the engine can never accept a move the page would not offer.
  • Line 651. The pipe |> passes the left value as the first argument of the next call. Read it as: log the action, then run it. That is why every engine function takes the game first.
  • Line 653. A bad move is a value, never an exception. The caller matches on the tuple, as play/3 did in lesson 1.
React ≈A reducer that returns {ok: true, state} or {ok: false, error} instead of throwing. TypeScript would type it as a union; here @spec says the same and Dialyzer checks it.

with: a chain that stops at the first miss

Quacks.Session wraps the game and keeps the list of moves. Its apply/3 uses with: if the right side of <- matches the left, carry on; if not, return that value as it is (with/1 docs).

An illegal move gives {:error, ...}, which does not match {:ok, game}, so with returns the engine’s error and the session stays as it was.

React ≈A chain of awaits where each step returns a result object, and the first failure short-circuits. No try/catch.

Why the random state lives in the struct

Game.new/1 seeds a random state and stores it in the struct: rng = :rand.seed_s(:exsss, seed) (game.ex:378). Every random pick reads g.rng and writes the next state back.

:rand.uniform_s/2 takes a state and returns {value, new_state}. It is pure. :rand.uniform/1, Enum.random/1 and Enum.shuffle/1 instead read a hidden per-process state, and AGENTS.md bans them in the engine. The payoff: the seed plus the list of moves rebuilds the exact game.

Undo is replay minus the last move. A bug report is a seed and a move list. A test can say “this seed draws these chips” (game_test.exs:40–46). Note the bare {:ok, game} = match in replay/4: a recorded move that is illegal on replay is a bug, so crashing is the right answer there.

React ≈Redux DevTools time travel, which works only if reducers are pure. Calling Math.random() inside a reducer breaks it; so would :rand.uniform/1 here.
